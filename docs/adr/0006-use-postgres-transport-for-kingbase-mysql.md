# Use Postgres-Compatible Transport for Kingbase MySQL

The **Kingbase MySQL Target** is surprising because it should generate MySQL SQL semantics, but local KingbaseES MySQL-mode verification accepted Postgres-compatible driver transport and did not complete a MySQL driver handshake. We will implement it as a target-specific Kingbase driver wrapper over the existing Postgres driver, expose a Kingbase-specific dialect class that inherits from the MySQL dialect, and normalize MySQL-style placeholders only at the Kingbase MySQL execution boundary so global MySQL and Postgres behavior remain unchanged. The inherited Postgres driver upload, stream, identifier, and metadata paths are viable against the local Kingbase MySQL database; the dialect should start from MySQL semantics but carry tested Kingbase MySQL overrides where inherited MySQL SQL is rejected, such as generated time series interval and recursive CTE typing.
